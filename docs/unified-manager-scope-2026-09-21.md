# 主管页面与团队范围统一（候选，未部署）

## 授权与问题

2026-09-21 项目负责人明确“凌子学管业务部和工程部”，并要求优化各角色页面。执行人为 Codex。对应账号为 `79727b73-5a54-40ff-bd1b-28dcf8d0bb23`，保持 `sales_manager` 及原 `team=销售部`；业务管理范围明确设为海外业务部、海外工程部。没有给 Chloe 增加跨团队权限，没有修改任何客户归属。

生产只读审计发现：询盘/客户部分读取按主管角色全局开放，而评分、风险按单个 profile.team 判断。导出已有单独双团队配置。此次统一的是业务管理范围，导出独立授权和双审批保持不变。

## 行为

- 新私有团队授权表及不可修改事件表。若存在显式配置，仅活动配置生效；全部停用后不回退到 profile.team。未配置的其他主管保留非空同团队规则。测试/非生产账号不获得管理范围。
- 凌子学的询盘、客户、商业沟通、报价、日报、评分结果和业务风险使用两个获授权部门；主管人员目录只列授权范围内在职业务员。
- 无主且有效的公共询盘保留共同分配入口；只有至少管理一个在职业务员的主管可见，分配对象必须属于其授权团队。已分配数据跟随当前负责人。无效无主数据、测试询盘、看板排除记录不向主管开放。
- 公司与联系人是共享主档，存在可管理询盘时可读该公司；公司级文件沿用公司归属模型。这不等于逐文件协作授权，跨团队共用公司的文件细分仍需后续设计。
- 日报人数、季度待评价表读取同一受控管理目录；月度评分、目标、校准、申诉、人才建议及风险列表、处置、扫描按授权部门判断。撤销范围使已有主管评价任务失效，不以曾经分配过任务永久授权。同行评价仍按同团队抽样。
- 主管详情增加“报价审核”；不展示创建报价或发送客户动作。RPC 同时拒绝主管新增报价、提交报价、记录销售跟进及修改联系人头像，履约写权限保留给老板/负责人。审核本人报价/本人业务申请被拒绝。
- 询盘写触发器作为受控工作流的第二层范围检查；31 个现行函数带原定义哈希检查，生产定义有并发变化时整笔迁移拒绝执行。

未执行生产迁移、角色切换、评分或客户分配。按安全基线6.1，本次生产权限变更需独立复核已确定提交后才可应用。
