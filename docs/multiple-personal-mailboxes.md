# 多个人邮箱 / 按业务员汇总

授权：项目负责人于 2026-10-28 明确要求按已确认方案开发、测试后上线。执行：Codex。当前为待发布候选。

- 登录身份不变，每个个人邮箱单独保存连接 ID、凭据、同步游标及邮件原件。新增邮箱不覆盖旧连接；同邮箱只能归属一个人，重连不能跨人或从公共邮箱抢占。
- 成员状态每人一行；任一邮箱 connected 即为已连接，显示连接数量，测试/同步时间取最新。市场/主管目录仍只获得原先批准的状态与时间字段，不增加他人邮箱内容权限。
- 个人收件箱读取本人全部关联邮箱，支持按邮箱筛选。发件选择必须在服务端再次验证本人、个人邮箱及 connected；多邮箱但没有明确选择时拒绝发送。回复默认原收件邮箱。
- 分类及收发汇总使用业务员 ID、收发方向、非空 RFC Message-ID 去重。没有 Message-ID 不猜测合并，不跨人合并；人工结果优先，同一邮件多份副本的人工分类冲突保留待确认。原件、分类事件及关联不删除。
- 定时邮件保存发件连接 ID；受限设置函数只能设置本人 pending scheduled 记录为本人 connected 邮箱，记录审计。原定时创建 RPC 保持 invoker、原校验与权限；未顺便修复既有定时权限或开启新派发任务。旧无连接 ID 任务仅在唯一 connected 时发送，歧义拒绝，不能静默换邮箱。

验收：1383 项 Node 回归、18 项邮件栈测试、浏览器脚本语法及隔离 PGlite SQL（双邮箱、唯一归属、按人去重、方向、空 Message-ID、人工优先/冲突、时间与每日对账、自身范围、匿名拒绝、定时选择跨人/已发送拒绝和审计）。没有真实邮箱凭据、邮件/通知发送或合成生产业务写入。初次邮件栈缺少本地锁定依赖，安装后通过；早期旧测试单邮箱断言已随行为更新。

迁移前需核对四个现行函数 MD5；唯一索引若有重复会原子失败。生产预检 8 个个人连接、484 份邮件、大小写规范化重复组 0、待发/发送中 0。迁移本身不改已有连接/邮件/分类/客户或账号，不扩大基础 RLS。

发布：正常 PR / 必需 CI / main / Pages；再原子迁移及部署五个受影响函数，保持四个用户函数 JWT=true、worker JWT=false + 原 worker token。生产版本/源码/公开资源和正常 UI 回读另记；测试通过不代表已经发布。

回滚：先停止新增连接及新定时安排，回退前端和函数时必须保留多邮箱兼容（不可直接恢复单邮箱读取/覆盖逻辑），保留所有连接/邮件/审计及新列；有多邮箱数据时不得重建每人唯一索引或删除第二邮箱。统计可恢复旧定义但会按副本计数，须明确口径。迁移前函数定义私有留存。新 SMTP/IMAP 实际凭据连接和外部送达不在本轮无发信验收范围。
