## 字段与口径

| 原表列 | CRM 补充方式 |
|---|---|
| 序号 | 当前筛选列表自动编号 |
| 大区、人员 | 人员由既有授权正式目录读取；大区按周期填写，不改变成员资料/安全团队 |
| 收集线索目标 | 市场部/老板填写周期目标 |
| 收集线索实际 | 默认服务器实际录入账本；历史汇总可由本人单独补录，标明来源，替代本报表数值，不与账本相加 |
| 收集率 | 实际÷目标 |
| 发送开发信目标 | 市场部/老板填写周期目标 |
| 发送总数、失效数量 | 业务员本人填写同来源、同周期完整汇总 |
| 发送成功、成功率 | 总发送－失效；成功÷总发送 |
| 已读、未读 | 已读须有可靠来源，不从回复推定；未读＝发送成功－已读 |
| 已回复、未回复 | 已回复由本人汇总；未回复沿用原表“已读－已回复”，明确标为“已读未回复” |
| 回复率 | 已回复÷发送总数，区别于原 CRM 的成熟样本七天回复率 |

目标和补录以人员与完整起止日期为唯一键，不自动按日分摊或继承到另一周期。周期≤93天、截止不晚于今天。缺失值为 null、明确零为 0、无分母不显示 0%；大区小计与可见合计只有该指标全员齐备才求和，比例由合计分子/分母计算。未知阅读数据不妨碍填写已知发送或回复数据，不补造阅读事实。当前在职目录不代表历史任职名单，未实现历史 HR 名单还原。

## 范围及存储

入口为原每日线索工作台“开发统计 / 指标补录”，复用上方周期和业务员筛选。两张表头行与原表一致，额外列显示来源与填写入口。现有邮件看板继续使用原口径，未把总发件当开发信、客户来信当开发信回复，未自动读取销售私有邮件。

独立私有 RLS 表 `private.lead_development_metrics`，普通/匿名/service 角色无直接表权限；公开窄 RPC 复用 `private.sales_lead_actor`。本人、原主管团队、市场部/老板读取范围与原线索工作台一致。仅市场/老板可写目标，仅正式在职业务员可写本人实际；主管只读。只读标记、测试/停用/非生产账号拒绝。来源说明不得填写客户、邮件正文或凭据。

写入按人员/周期加事务锁、校验 expected_revision，冲突拒绝而不覆盖；修改目标保留实际，修改实际保留目标。读写追加原不可变 `private.sales_lead_events`，保留执行人、周期、动作、时间及修改前后内容。不改原线索录入时间、日报、客户归属、邮件、绩效和历史周报；不创建导出或外部 AI/消息通道。原未完成的市场导出分支未纳入。
