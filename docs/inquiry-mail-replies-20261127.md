# 询盘邮件回复情况与90天历史沟通记录

授权：项目负责人要求自动调取业务员询盘的邮件回复情况，确认回补最近90天，并要求清晰的聊天记录。不发送邮件、不触发旧信提醒，不调用外部AI。只处理原有本人/主管团队/老板权限范围，市场部不增加销售私有邮件权限。

## 行为与边界

- 官方询盘列表自动显示已同步及已回补的回复证据、最后来信/发件/回复时间、同步缺口。详情顶部可直接打开“邮件沟通”。在可见页面每60秒核对，页面关闭后历史任务由后台继续。
- 回复须为当前负责人在本次分配后发给原客户、且有匹配邮件线程头的实际发件。分配转发、草稿、待发送、其他负责人和未来时间不计为回复。重复邮件副本不制造新来信；时序冲突保留待核对，不评分、不改业绩。
- 历史按服务器收件时间固定最近90天，仅通过已有关联邮件的 Message-ID / In-Reply-To / References 精确回补，不按客户名、主题相似或单一邮箱强行归项目。缺少线程证据、容量或连接异常单独说明，不能把无记录当成没有回复。
- 沟通记录按实际时间排列，保留发/收件人和正文。邮件引用折叠在本封原文内，不虚构新的聊天消息；只展示纯文本，HTML脚本、外部图片、追踪链接不自动执行。重复副本优先完整正文。大正文标记不完整，不静默截断。
- 通过只读 IMAP 读取正文 MIME 部分，不导入附件、不改已读/未读或其他邮箱标记，不发送 SMTP、邮件、群通知或外部AI请求。

## 受控接口与调用方

独立 `inquiry_mail_history` 保存历史证据，不向 `email_messages` 写入，避免原新回复、SLA、报价、AI和跟进触发器。状态模块只读元数据，沟通模块逐页读取正文。正文只经有范围检查与审计的 RPC 获取；客户端不能直接读取正文列或写历史。原邮件同步、业务表和既有导出固定字段均保持；不把历史邮件加入导出。

新后台函数 `inquiry-mail-history`：普通入口保留 getUser、启用生产账号、原询盘RLS和只读保护。定时入口只允许既有服务端 worker token，且只能继续由验证过的员工发起的任务，不能自行发起。网关 `verify_jwt=false` 是该混合入口的部署配置；用户身份由 handler 验证，不是匿名接口。后台 token 不返回给客户端，不新增或导出 Secret。

私有请求/任务保存90天固定窗口、原负责人、租约、游标与计数；每日同发起人/询盘/负责人幂等。每次领取和每次实际追加均复核账号、范围、当前归属与有效租约；停用/移交后停止。历史正文追加不可覆盖；合并后的读取按当前主询盘权限解析，不保留原负责人的越权访问。后台任务、捕获和正文查看保留审计。

代码调用方仅：`assets/inquiry-mail-replies.mjs`、`assets/inquiry-mail-conversation.mjs`、新 Edge。既有合并/归属流程不写历史表，读取时解析主询盘；不改旧同步游标、首次响应、跟进和提醒。当前IMAP允许已批准邮箱连接上的固定公共服务商993/TLS，未配置、非支持主机不尝试连接。

## 发布与回滚

1. 安装 `20261127090000_inquiry_mail_history.sql`，核验表/函数权限与原表未改。
2. 仅部署新 Edge：`supabase functions deploy inquiry-mail-history --project-ref plhverjihjilnuhlhlxi --use-api --no-verify-jwt`。匿名与错误 worker token 必须401；正常用户读权限与范围必须检查。
3. 安装 `20261127091000_schedule_inquiry_mail_history.sql`，只增加 `crm-inquiry-mail-history-worker`，沿用 Vault 的既有 worker token/公共API配置，不输出值、不修改旧同步任务。
4. 发布 index/Grace 与新模块，正常授权会话核对状态、历史任务、沟通原文及刷新回读。

回滚：先停止新 cron `crm-inquiry-mail-history-worker`，恢复前端，必要时停用新函数/收回新RPC执行；旧邮件同步不停止。保留全部历史证据、请求、失败、正文查看和权限审计，不DROP表或重写旧状态。

## 验证口径

纯逻辑、模拟IMAP和隔离PostgreSQL仅使用合成数据。覆盖线程证据、重复副本、转发/其他负责人、分页和读取缺口、纯文本/XSS、失效/跨范围/只读、租约、追加幂等和合并后归属。生产状态、真实回补数量与剩余缺口以 WORKLOG / DEPLOY_AUDIT 的发布验收记录为准，不能以离线通过替代实际回补完成。

API契约核对使用固定版本依赖及 [ImapFlow 官方读取文档](https://imapflow.com/docs/guides/fetching-messages/) 和 [download / UID API](https://imapflow.com/docs/api/imapflow-client/)；不使用第三方文章作为技术依据。
