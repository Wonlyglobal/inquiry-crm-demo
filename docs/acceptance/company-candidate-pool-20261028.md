# CRM 线索公共池：背调候选接入

## 目标与来源
用户确认把“国家背调系统 / 增加海关客户联系人线索”任务的背调客户导入独立CRM线索公共池。源任务现有交付是公司级CSV，不是联系人数据：1766行，1323官网域名候选、443第三方候选，均未完成官方核验。原2386条中已排除574地图来源、36无有效HTTPS来源、10重复项。当前任务不读取原始联系人库、不运行TopEase、不发送邮件、不调用外部AI。

真实清单仅本地预检：`/private/tmp/wonly_public_pool_import_stage_2026-10-28.csv`，SHA256 `d8f6bc29ad28735268b3d0a67634e4fae8ee772c4839a0fce30d15ad9b3b13fd`。实际SheetJS解析1766条，字段与CSV读取逐字段一致；公司/国家规范化无重复组。发现并修正国际化域名punycode顶级域的误拦截。源数据不提交到仓库。

## 数据与权限
- 左侧“客户与商机”增加“线索公共池”，与原询盘“客户公海”、个人“每日线索”分开。
- 新私有公司候选、来源、批次回执及不可变审计表，RLS开启，客户端与service_role不能直读写。仅原正常活动生产成员入口，无账号或JWT能力扩张。
- 市场/老板可导入和提交公开身份核验；不能从文件的“已核实”标志获得认可。每次核验记录官网、说明、操作者、时间。
- 业务员仅本人领取已核实且未占用候选，再补充需求/跟进方向与实际获取日期，受控调用原record_sales_leads进入本人线索。导入、核验、领取不计个人量；转入后使用原录入日期、日报、去重、联系方式待补充与转商机守卫。
- 服务端对已有私有线索、客户商机及领取人核对。非负责人（老板原全局治理范围除外）只能收到负责人姓名及状态，不返回候选ID、公司、国家、域名、来源或个人线索ID；搜索隐藏公司不命中。停用人员的历史归属继续保护，不自动释放；商机换负责人/未分配状态也阻止重新领取。
- 公司名与域名身份冲突拒绝整批，不自动合并；重复导入只追加公开来源，不覆盖审核或领取。每批200条、文件2000行/2MB，稳定批次ID+输入摘要回执支持中断后原批次重试。成功回执前不推进进度；部分批次已保存明确显示数量。
- 无联系人、邮箱、电话或私人备注列；拒绝地图、邮箱平台、非HTTPS等来源。海关历史记录只作待核实候选，不推断当前采购需求。没有批量导出入口或浏览器长期存储。
- 每分钟导入20批、查询60次、核验/领取/转入各30次的独立审计限流；原调度和消息设置不变。
