# Grace 受控实时语音

2026-10-15。部署和真人验收状态以项目工作日志为准。

## 行为

保留一个麦克风与 AudioContext，在录音、识别、思考、播放期间接续本机监听。600ms 停顿结束当前讲话；500ms 本机预录保留插话开头。播放参考和短暂降音确认过滤回声；没有可靠参考时保留手动打断。

新 agent-realtime WebSocket 通道使用百炼北京 Qwen3.8-Omni-Flash-Realtime，16kHz PCM 输入、24kHz PCM 输出，Tina 合成音色。服务端手动提交和启动回答，浏览器不能发送任意模型事件。接通后边说边传，逐个约4秒的分段通过公司内部声纹核验后才送百炼；短句在结束时校验；注册声纹后有效语音少于公司模型要求的2.5秒时会要求重新说完整一句，不会把短句误当本人。长段校验积压最多8秒，超限停止，不绕过门禁。说话人不明确、他人或服务不可用均不转写、不回答。未注册状态沿用既有规则。

公开通用对话由实时模型流式回答，第一段到达就安排播放。产品、CRM、内部资料、联网、模糊追问等问题关闭本轮原生回答，携带与准确转写绑定的短期声纹凭据交给现有 Grace 路由；内部资料正文不回传实时模型，仍由内部服务处理。内部问题语音沿用固定安全提示，不把内部参数读给外部 TTS。实时通道未配置或未启用时沿用既有逐轮通话，不将其标为实时。

插话、静音、挂断会取消旧播放与轮次；正在生成时向提供商发送 response.cancel 并关闭该轮连接。迟到分段忽略，只有完整播完的公开回答进入实时上下文。前端取消不能保证消除取消前已发生的提供商计费。录音不持久化，不在浏览器保存会话凭据或原始音频。

## 身份与限额

仅沿用现有精确 owner 身份、active 角色及 BAILIAN_AGENT_POLICY；不开放其他用户，不改变 RLS。服务密钥只用于既有 audit_logs 元数据写入及计数，不读取客户表。浏览器 JWT 仅放首个 TLS WebSocket 帧，5秒内验证；不在 URL、日志或存储中传递。每轮再次核验身份和策略。

每分钟沿用12次 agent_bailian_request 审计软限流；连接和合成诊断分别2次/分钟。没有新增数据库或放宽既有配额；软计数不是原子硬配额。每次讲话45秒、通话20分钟、空闲60秒；所有缓冲与模型输出有上限。工作线程连接135秒上限；新轮次若连接超过45秒，按签名短期状态续接，重新验证用户。异常长轮次触及硬上限会明确结束，不能宣称无限无缝后台通话。

## 配置、检查和回滚

新函数需要既有 DASHSCOPE_API_KEY、BAILIAN_AGENT_POLICY、公司声纹签名配置，另设 BAILIAN_REALTIME_WORKSPACE_ID 与 BAILIAN_REALTIME_POLICY=bailian-realtime-guarded-v1。workspace 必须是当前北京业务空间。密钥留在服务端，不创建浏览器临时提供商密钥。

先部署关闭状态，核验公司声纹服务状态（不读取模板或登记录音），再使用主动点击的“检查实时语音”发送固定公开问候文本，检查提供商权限、PCM配置、实际音频分段及首段时间，并将同一固定公开问候的合成音频回送做转写与手动模式检查；启用后还核验浏览器认证通道；不采集麦克风，不构成真人 ASR、声纹、端到端响应速度或 iPhone 外放验收。通过后再启用策略并核验已登录状态；匿名状态请求应拒绝。再核验连续提问、回声、插话、静音和挂断。

回滚把 BAILIAN_REALTIME_POLICY 改为 disabled，前端连接检查回到原通话；必要时回退本次前端与新函数。不删除知识、业务资料或审计。不声称已安装新的原生包、PSTN电话或离线后台通话。

依据（2026-10-15查阅）：[百炼实时模型与地域接口](https://help.aliyun.com/zh/model-studio/realtime)、[客户端受控事件与输入转写配置](https://help.aliyun.com/zh/model-studio/client-events)、[服务端事件](https://help.aliyun.com/zh/model-studio/server-events)、[Supabase WebSocket](https://supabase.com/docs/guides/functions/websockets)。因既有声纹前置和内部资料边界，未采用直接浏览器自动 VAD 上云。

兼容性核验：真实提供商在关闭VAD后省略 turn_detection 字段。只接受缺省或显式null且16k/24k PCM完整回显；任何VAD对象均拒绝。合成回环追加一秒静音，核验输入转写并等待一秒，出现未经 response.create 的回答即失败；仍保持声纹和回答路由门禁。

连接预热期间麦克风回调合并为100–200ms帧，避免握手后瞬间发送大量小帧触发限流；队列最多8秒，允许匹配该队列的有限时钟突发。通过声纹的4秒分段再拆为200ms小帧、按实际PCM样本时长送给实时模型（200ms音频间隔200ms，末帧按长度计算），取消时立即停止剩余发送。诊断的合成输出和音频输入采用独立模型会话，以贴近真实电话的输入先行时序；公司状态与模型诊断并行，失败均关闭资源。

生产合成验收发现：突发发送时可能只有转写增量而无完成事件；固定公开音频按实时样本时钟发送后，完整转写、手动回答门禁和浏览器认证网关均通过。实际通话沿用该节奏；公司声纹前置分段仍会引入缓冲延迟，合成首段音频时间不等于真人端到端响应速度。

通话防饿死修复：本机短校准和持续低幅稳定背景声估计用于结束当前讲话，不承担身份判断。识别/准备回答期间的新语音先保存在有界本机片段中，旧回答继续；该排队片段随后沿既有声纹/ASR路径处理，不创建并行实时轮次。播放时仍可自动插话；若连续两次取消后又检测到第三次插话且未完成任何回答，本次通话暂停自动打断并提示手动打断，避免整通电话没有回复。下一次显式通话恢复自动模式。声纹录入直达按钮只打开并定位登记入口，不自动录音；通话中登记要求先挂断。
