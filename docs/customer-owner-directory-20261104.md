# 业务员客户列表与线索入口区分

## 本次范围

依据项目负责人于 2026-11-04 确认：客户管理应按业务员展示，区分自主开发/登记、官方分配和转介绍，并与日常客户线索分开。执行人为 Codex。

旧三栏公司/联系人/商机选择器改为分页列表与右侧快速查看。每条列表记录是一个“客户公司＋当前负责人”，不是新的客户或商机业务记录；同一公司多人负责时分别显示归属，但总客户数按公司去重。只展示当前用户原 RLS 可读且已有负责人、未归档/合并的记录。未归属官方询盘仍从原官方询盘及待分配入口处理。

来源复用既有 `get_inquiry_channel_origins` 受控只读投影，不依据可编辑渠道猜官方来源。个人登记来源即使填官网也保持自主登记；个人记录中的转介绍单列；证据不全显示来源待核对。原审计不区分所有历史手动和 Excel 方式，因此合并展示“自主开发 / 登记”，不编造历史导入方式。

联系人仅取当前归属记录明确关联的 contact_id；快速查看不按公司聚合其他归属的联系人。最近跟进和下次行动来自原授权 follow_ups/inquiries 技术日期，不读取邮件正文、跟进内容、交易材料或调用外部 AI。完整档案与关联询盘复用原入口和服务端权限。

日常未转化线索继续在独立线索账本中。导入按钮先区分日常线索与已有客户档案：业务员日常线索进入原线索工作台，管理账号不代业务员录入；已有客户档案保留原文件导入与明确选择。没有迁移历史导入、修改客户归属、自动转化或重算日报/业绩。已推进/待跟进只描述现有阶段，不能当成新的正式商机认定。
