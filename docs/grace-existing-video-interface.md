# Existing internal video index: limited internal release

This candidate uses the current signed material `knowledge` interface and original owner private-metrics RPC. It does not require SSH, a new material operation, cloud video inference, new credentials, RLS, tables or platform scopes. No media files are downloaded or published. The new `agent-video-preview` endpoint only accepts authenticated original-owner text video questions; it does not expose general model/voice/tool operations. `?video-preview=1` selects that fixed endpoint for video text questions only. The opt-in preview was actually tested before enabling the same implementation on `agent-conversation`. Social receipt actions now expose “视频证据”; normal text/voice behavior and source sync are unchanged. The preview remains an owner-only acceptance route.

One video request reads two adjacent material pages, capped at 20 rows each, using an empty segment query. The existing source otherwise filters video segments by the filename query and can omit already indexed speech/OCR/visual evidence. Non-video rows are immediately discarded, never shown or sent to models. Only bounded video metadata and up to six existing segments per video are retained. Pages, failures, source read date, original segment start/end, truncation, current/historical registration and a response-projection digest remain explicit. The digest is not a source-file checksum or a persisted video knowledge receipt.

Saved metrics and material video observations are independent evidence blocks. There is no verified publishing binding in this interface. Never pair by similar titles, imply a material is the original published version, explain a particular post's performance using an unpaired material, or call a cumulative view count three-second retention. Source file hash, parsing completion date and full frame coverage are not supplied. A registered current version does not establish index freshness. OCR is screen text, not necessarily subtitles; ASR and model visual descriptions need human checking. Crossing/unknown ASR endpoints do not establish exact opening wording. Missing streams, captions, timestamps or metrics stay unknown.

The response offers timestamp-specific editing experiments and bounded ASR word-unit / filler / OCR length checks only where readable evidence exists, plus known-metric review priorities, 24h/72h comparison and explicit pairing/retention/attribution gaps. It performs no posting, edits, knowledge imports or metric-source-time updates. Future per-post causal or published-video analysis requires verified publishing identity/version evidence; it is outside the acceptance claim for this limited interface.

Acceptance: synthetic malformed/date/size/duplicate/SSRF/binding-gap tests first; normal PR CI; deploy the narrow preview; actual owner questions with source pages, modality counts, projection digest and original private knowledge ID/hash; missing-date/unsupported-period/failure cases. Do not release based only on syntax or unit tests. Rollback the paired frontend/backend code through normal review/CI and disable/delete the preview after confirming no caller depends on it; preserve original snapshots and source audit.

Actual preview acceptance used the original owner session: all four saved platform receipts, independent content readback, readable visual/ASR/OCR segments on later material pages, fullwidth input, short follow-up page retention and missing-date handling. One page pair initially failed, then a later explicit request succeeded; the original failure is retained in private evidence and is not treated as no content. Full continuous opening coverage, original published-video binding and real editing outcomes are not accepted claims. No per-post video performance diagnosis has been verified. Real media/text/metrics and acceptance captures remain only in private project artifacts.
