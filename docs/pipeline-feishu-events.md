# 询盘流水线飞书提醒

2026-11-02 项目负责人要求所有流水线业务进度推送到其指定群，且明确确认群成员均获准查看基本需求摘要。本次新增独立目的地，不改变线索日报/周报的目的地或成员权限。真实 webhook 仅在服务端 Secret，通过不回显标准输入配置，不进 Git、临时文件、日志或前端。

## 事件与内容

数据库事务提交后的事件覆盖公共邮箱进入、分拣、市场分工/背调完成/登记/转发进度，以及询盘九阶段、有效性/无效申请、分配转派、基本需求、采购条件核实、首次有效联系、后续跟进/培育计划。仅监控列发生变化才入队；普通刷新、updated_at、未改变业务字段的保存不入队。邮件转询盘合并一条，同一事务同一记录合并最终状态；事务回滚不通知。只有启用后的自然业务变更，绝不回放历史；旧邮件首次同步不冒作新到邮件。个人邮箱不在 email_intake，不新增个人邮件广播。

消息包含编号、事件与进度、基本需求（产品门类/国家地区/数量）、下一责任人及动作、事件时间、原权限 CRM HTTPS 链接。分类和国家来自封闭别名，数量仅数字/范围与固定单位；未知显示待核实。不发送自由文本需求、邮件/附件、主题、联系方式、报价金额、合同、付款信息或核实笔记。自由文本需求/核实笔记改变仅通知“已更新”，内容回 CRM 查看。不调用 AI。新未关联邮件没有结构化需求，只显示待核实。

责任人取事件快照的现有业务员、邮件市场负责人或唯一覆盖主管；未知或多主管显示对应角色“待指定”。动作是工作建议，不改变客户归属或原审批。不是飞书 @；机器人没有群成员目录权限。姓名不接受换行、URL、mention/标签。每条消息标明以 CRM 当前状态和权限为准。

测试、非生产、归档、看板排除询盘不发送；派发时再次检查。公共邮件表本身无环境标记，按现有公共邮箱入口接入，关联后继承询盘排除规则。

## 发送与防重复

迁移默认关闭。private 三表 RLS 且没有 anon/authenticated/service 直读写授权；业务触发器只追加队列/不可变审计，不改原业务字段。service-only RPC 验证 JWT role、目的地 SHA256、行租约；普通用户只可查询原角色范围内的入队布尔回执。工作器先校验原 MAIL_SYNC_WORKER_TOKEN，严格固定官方 HTTPS hook 主机/路径；不接受请求中的正文或目的地，无旧群回退。

CRM_PIPELINE_FEISHU_WEBHOOK_URL 与 CRM_PIPELINE_FEISHU_ENABLED 仅服务端使用。数据库目的地摘要与批准人/原因绑定。单独每分钟 cron，单次最多10条，30秒领取节流，500毫秒发送间隔，10秒网络超时、10分钟租约、最多5次指数退避。并发 SKIP LOCKED；成功回执不再领取；耗尽保留失败和全部审计。网络已送达但回执丢失时，重试可能重复，属于至少一次送达，不能承诺飞书端严格一次。

新开关生效时原 group-notify/feishu-notify 仅确认事务队列，避免浏览器重复发飞书；原钉钉保留，日报/周报函数和 Secret 保持。前端显示提交，不把排队当送达。

## 发布与验收

正常 PR/CI；先安装默认关闭迁移，核对来源/ACL/RLS/原业务哈希；部署与下载比对新 worker 和两个旧入口，再配置专用 Secret/数据库批准信息和调度，最后启用。Secret 切换和 DB 开关存在短维护窗口，旧入口可能暂报“不可确认”，业务保存与队列仍保留，不回退发旧群。

隔离 PostgreSQL 执行真实迁移，验证事务/去重/九阶段/权限/租约/退避/失败/排除；离线测试投影、固定目的地、鉴权、发送失败与旧入口。允许一条不含真实客户/人员/业绩的固定连接消息验收；不制造真实客户/阶段、不回放旧业务。自然真实业务的端到端送达需后续真实操作发生后观察。

回滚先关闭 DB enabled 与服务端开关，并暂停仅 crm-pipeline-feishu-dispatch；恢复经备份核对的两个旧入口源码和前端。保留队列、审计、原客户数据与全部既发证据，不删除已发消息或通知记录。逐项确认旧入口恢复的原群仍是授权目的地；不能把停止新路由误作允许转发到旧群。其余治理风险不因此关闭。正式生产状态详见项目 WORKLOG/DEPLOY_AUDIT 与私有验收目录。

## 单人真实提及候选（2026-11-02）

用户要求直接 @ 指定成员，个人账号外部群场景不要求企业空间。官方规则：外部群单人提及仅支持 Open ID，自定义 Webhook 不具有读取成员/反查姓名的能力；参考[自定义机器人使用指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)和[外部用户与应用机器人](https://open.feishu.cn/document/develop-robots/add-bot-to-external-group)。个人实名认证的应用机器人可支持外部用户主动单聊后获取 Open ID；尚未创建应用、扩大权限或操作实名认证。

候选新增仅服务端 CRM_PIPELINE_FEISHU_MENTION_OPEN_ID / CRM_PIPELINE_FEISHU_MENTION_NAME 可选绑定，严格 ou_+32位hex和单行姓名，拒绝 all、CRM UUID、标签、URL和不完整绑定。只允许服务端可信配置生成一个真实 at 标签，浏览器请求和事件正文不能指定被提及者；正文需求/原权限/队列范围保持。未配置时原消息不变，错误配置拒绝派发，留队列等待纠正，不降级伪装成已提及。

没有取得且核验指定成员有效 Open ID 前，不配置或部署提及，不把姓名展示当成功通知，也不改成 @所有人。当前生产仍是PR459文本姓名。待完成账号绑定后正常CI发布，明确单条提及验收；不要重发历史业务消息。回滚仅恢复 worker/shared 源码和撤销这两个专用提及设置，保留原路由、队列及审计。
