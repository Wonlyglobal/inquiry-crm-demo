# 个人邮箱内容分类与数量排行榜

授权：2026-10-23 项目负责人要求按九类优化、加入个人排行榜、测试后上线；另明确批准百炼北京必要脱敏分类范围，不包含附件、完整线程、高敏内容或自动业务处置。

九类为新客户询盘、客户回复、报价及订单沟通、售后、业务开发信、营销推广、系统通知、疑似垃圾邮件、待人工确认。只统计已同步个人邮箱，分类不等于询盘有效性。人工确认和 AI 建议分开，默认榜为人工确认；零和缺失均不生成第一。此榜不影响员工能力、360评分或既有绩效规则。

## 人工复核清单

入口：经营看板→排行榜→业务员邮件内容分类与数量榜→人工复核清单。按业务员、月份、状态筛选：全部待复核（skipped或AI uncertain）、安全跳过、AI待人工确认、已人工复核。服务端先过滤再每页50条，稳定时间/ID排序；不把已确定但尚未人工确认的AI类别混进120项待复核队列。

逐条点击“查看原邮件”，在同一页展开完整纯文本（含引用历史），不标已读、不发信、不读取附件/HTML、不送外部AI；无纯文本需在原邮箱核对。按当前原文hash读取，变化或权限失效拒绝，写查看审计。理由解释高敏规则信号/无安全短语/证据或置信度不足，不把跳过当垃圾。选择类别、填写至少5字真实依据后保存，使用既有review_sales_mail_type追加事件；人工确认优先、旧建议保留，已确认项退出待复核队列，可在已人工复核中继续纠正。业务评分与原邮件不变。

新增两个RPC均复用private.sales_mail_type_scope/detail，匿名拒绝，主管未关联私人邮件仍不可读；没有新角色、RLS或外部模型范围。前端丢弃切换筛选/关闭后的迟到结果，原文只在当前DOM、不持久缓存；未提交理由仅在本次窗口内按消息/hash保留，关闭/刷新不会持久保存草稿。上线顺序新RPC迁移后前端；回退前端后撤销两个新增RPC执行权，保留审计及人工事件，不回滚其他邮件功能。

新端点 sales-mail-types：显式请求、每批最多2封、客户端一次最多20批；认证用户+既有RLS读取单封正文，固定 qwen-plus / 百炼北京 / bailian-redacted-mail-types-v1。仅发送从当前正文匹配到的固定通用词组与方向，所有自由文本、标头、身份、金额、附件和线程均不发。先扫描整封正文及主题的付款/银行/证件/凭据等高敏线索，命中即跳过；无安全词组亦跳过。该最小化会降低识别覆盖，不能声称完整语义理解；新客户身份无法证明时必须待确认。置信度低于0.7也归待确认。

模型结果只采纳枚举、数值置信度和逐字命中的安全短语；理由为系统固定文案，模型自由文本不保存。原文hash防陈旧结果，人工纠正追加并优先，不覆盖历史。每请求/结果/人工复核留审计；同原文同策略幂等，失败单列且不自动重试。30批/10分钟/用户，数据库事务锁限流。

仅老板/本团队主管/本人可看聚合；明细复核进一步限制本人、老板或主管既有询盘管理范围，未关联私人邮件不因此对主管开放。新表RLS、authenticated仅SELECT，服务角色也仅SELECT；写入只经受控RPC，模型写RPC仅service_role，普通用户不能伪造模型结果；历史拒绝更新/删除。排除测试账号与已关联测试询盘。无原邮件/询盘/评分/客户权限改写。

验证：离线安全/方向/模型校验/渲染和数量测试；新DDL和单封合成邮件同事务保存、回读、去重、人工优先、源版本、跨人拒绝、ACL、历史不可改验证后全部回滚。生产实际版本、模型、UI与回读须另记发布记录，不能以测试通过替代上线。
