# 邮件识别与流水线核对

规则版本 mail-pipeline-20261127-v1。按用户“做这个识别功能”实现于官方询盘详情的邮件沟通记录；index 与 Grace 共用规则与展示。

只用当前账号经原 RLS 已加载的已关联邮件，在浏览器执行规则，不上传正文给外部 AI，不自动发信或写阶段。每类展示最近一封及原文定位；加载范围不等于完整邮箱。客户询价与我方报价分别标示；实际我方发件须核对负责人地址、客户地址、发送时间以及金额或实际附件。转发、草稿、未来承诺、引用旧文不作为已发送证据。历史/截断/身份不明确记录只供核对。

报价入口沿用原审批及发送流程，寄样沿用凭据登记，接受报价只是订单意向，不能自动成交。仅负责人业务员或老板可核对；主管仅查看。谈判仅从已报价/已寄样带入，先确认再填写，仍需显式保存。保存复核负责人、旧阶段、版本，冲突不覆盖，来源邮件编号及规则版本写入原修改原因。权限与业务审批不变。

验证：2877 项离线测试全过，包含实际页面核对/保存处理器的 VM 测试，覆盖取消、只带入不保存、并发冲突、无权账号、报价/寄样路由及来源留痕。浏览器语法和 diff 检查通过。本机合成页面以实际控制器与实际处理器验证取消保持原阶段、带入后尚未保存、显式保存后重新加载不再重复推进、原文定位；窄屏无横向溢出。合成保存不代表生产业务写入验收；未修改真实询盘、未发送邮件。

局限：规则匹配并非通用语义模型，可能漏掉非典型表达/未同步或未精确关联邮件，不据未命中推断“没有回复/报价”；识别结论必须结合原文与业务凭据核对。无新增数据库/Edge/后台任务；回滚恢复本次前端变更即可，原邮件与记录不删除。
