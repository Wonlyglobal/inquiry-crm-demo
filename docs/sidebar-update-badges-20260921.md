# 侧边栏更新状态

用户要求新询盘在待分配池显示红点和数量，其他业务页同样提示更新。

待分配池使用与列表一致的有效、pending_assignment、excluded_from_dashboard=false精确计数；邮件分拣使用未分拣且未删除邮件计数。其他业务页按当前用户未读通知type归类，覆盖询盘、跟进、邮箱、WhatsApp、沟通、报价、履约、公海、培育、背调、日报、评分、风险、知识、模板、客户、历史工程；未识别类型落到经营看板。没有相应通知事件的内容变更不会自动产生红点，不把库存总数假装为新更新。系统设置及操作指南无业务未读来源，保持无标记。

红底数字含小圆点，超过99显示99+，悬停和无障碍名称保留准确数量。待办不会因打开页面而消失；通知已读后更新。复用通知Realtime订阅，INSERT提示toast，UPDATE/DELETE仅刷新；每30秒及页面恢复可见时只读补查。后台隐藏时不轮询，单请求组互斥，身份变化拒绝旧结果，错误不覆盖为0。

只读取当前账号RLS允许的数据，notifications额外限定recipient_id；无数据库、权限、用户资料、通知生产器或函数更改。刷新只获取计数及通知id/type/read_at，不批量加载客户正文。

验证：浏览器模块语法、322项离线回归、diff检查通过，新增测试执行实际归类函数验证通知类型、已读和去重。尚未生产发布/浏览器验收。回滚为受保护PR回退前端。PR22直接分配入口独立在审，本分支基于已发布main，互不依赖。
