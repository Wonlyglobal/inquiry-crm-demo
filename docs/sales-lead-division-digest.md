# 事业部线索与商机汇总推送（候选，未部署）

授权：2026-10-27 项目用户要求“统计整个事业部，按照排名，一条推送”。执行：Codex。

## 口径

- 事业部范围沿用现有线索调度器：全部 active、role=sales、非测试、production 人员；不以是否连接邮箱或是否录入来排除成员。不改变组织、客户或销售个人内容权限。
- 日榜：按服务器录入北京时间当天的新增数量降序，同量同名次；逐人显示当日转商机数量及达标、无新增申报、未提交、未达标或豁免。全员汇总含上述状态人数。缺少线索登记不等于“未正式提交销售日报”，文案明确区分。
- 周榜：按本周转为商机数降序，再按本周新增数降序，两项相同同名次；旧线索本周转化不算本周新增。使用原个人不可变周快照，附跟进、无新增申报/未提交/不足目标人天。
- 默认仍为工作日17:00、周五16:00，市场未来规则版本仍生效。日榜等待当日冻结规则中最晚提醒时间；周榜等待全部合格成员的本周快照就绪，避免规则调整后只推部分人。
- 每日/每周各一条群消息；周五两个不同时间的日榜、周榜各一条。站内个人及原主管范围通知保留；不把全事业部明细广播到新增站内人员。
- 群只收姓名、部门和计数/状态，不收客户、联系方式、原邮件、需求、金额、无新增或请假原因。并列排序用姓名、ID稳定显示，不作绩效或人事决策。

离线PGlite合成库：25项SQL断言，覆盖全员含零量、排名及并列、截止后录入排除、旧线索本周转化、无新增/豁免原因不外传、站内提醒保留、个人队列被替代、每日周重复、周末、冻结周截止不同不漏人、权限及租约。开发目录1375项Node回归包括另一个未发布的成员筛选候选；发布时只选本功能文件、从精确提交另跑。用户随后批准发布；生产只读三个原函数体与仓库MD5一致，迁移新增同源指纹保护。无真实客户数据查询或飞书/邮件发送；最终部署状态以项目部署审计为准。

发布前：负责人批准精确迁移；核对现行调度/claim函数原定义与当前源码、现有cron和派发调用方，保存定义/ACL与队列前态；先暂停派发并等在途请求结束，再执行迁移和最小只读回读后恢复原调度，防止旧版本在途逐人消息。实际首个自然周期数量与看板对账待验收，不因本地测试通过宣称上线。

回滚应使用前向受控迁移恢复原调度/claim定义并保留新列、历史快照、通知、队列和审计；claim继续排除已替代记录，新汇总未发送记录以明确替代原因停派，不重新派发历史逐人消息。不得删除证据、清空队列或把未发送状态改成功。
