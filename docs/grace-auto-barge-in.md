# Grace 连续通话自动插话

2026-10-15，沿用已批准的百炼北京 ASR/TTS、声纹证明和内部物料路由。候选功能；生产发布状态以项目 WORKLOG 的发布证据为准。

主动开始通话后，Grace 播放回答时本机继续监听。一个麦克风和 AudioContext 在整次通话复用；模型/转写请求仍按轮串行，不开放持续云端监听。用户插话确认后，旧播放及浏览器请求立即取消，下一轮复用正在录制的完整片段。服务端原有身份、声纹和材料隔离不变。未增加供应商、权限、持久录音或数据库表。

本机回声防护分三层：请求浏览器回声消除与降噪；以当前播放的 PCM 参考比对最近 450 毫秒的明显延迟回声；有持续候选声音时将播放短暂降音，等待 140 毫秒尾音消退，再确认至少 100 毫秒仍有非相关声音。未确认则恢复播放，不转写，不取消旧回答。该规则是声音候选检测，不是说话人身份认证；新问题依然必须通过原声纹门禁。它不能保证过滤所有房间回响、电视或旁人声音。

本机 PCM 预录环形缓冲 500 毫秒，保存插话开头；只在整段结束后发送至既有转写接口，静音和未确认片段不上传。单段仍最多 45 秒；60 秒闲置、20 分钟上限、静音、离开和离线清理均保留。停顿判定由 750 缩至 600 毫秒；没有声称改变了云模型实际首声耗时。诊断区分请求到首声和片段就绪到首声，不记录原文。未播出的云回答不提交为已听过的会话历史。

无法建立播放参考的浏览器，在播报时不自动确认插话，并明确提示使用手动打断；思考期间仍能接听。保留手动打断、静音和挂断。自动插话仅用于明确开始的连续通话，原 Hello 唤醒模式不变。

这实现的是浏览器同时播放和监听以及本地自动打断。现有 ASR→问答→TTS 仍是按轮接口，尚非端到端双向音频流；浏览器取消请求不保证供应商立即停止服务端计算和计费。iOS/WKWebView、耳机切换和真实扬声器回声需真人真机验收，合成音频不能替代。

开发依据：[MediaTrackConstraints.echoCancellation](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/echoCancellation)、[AudioContext.createMediaElementSource](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaElementSource)。浏览器 true 设置是尝试消除回声，不能当作声学验收。未更换现有语音模型或将内部资料交给外部模型。

回滚：回退本次前端模块及入口版本至 PR266 的连续通话版。无数据迁移；保留既有资料和审计。发布前离线回归、合成本机浏览器双音源/回声/取消/静音/清理验证；发布后验证 HTML 与模块 SHA256。真人效果未测时必须保留该限制。
